# 思考指南

> **目标**：扩展你的思考范围，提前捕捉那些容易忽略的问题。

---

## 为什么需要思考指南？

**大多数 bug 和技术债来自“没想到这里”**，而不是不会写代码：

- 没想到层与层的边界会出问题 → 跨层 bug
- 没想到同一模式在重复出现 → 到处是重复代码
- 没想到边界情况 → 运行时错误
- 没想到未来维护者 → 代码难以理解

这些指南的作用，是帮助你在编码前**问对问题**。

## 快速参考：什么时候该想一层

### 什么时候该考虑跨层问题

- [ ] 功能触达 3 层以上（API、Service、Component、Database）
- [ ] 数据在层之间会发生格式变化
- [ ] 多个消费者需要同一份数据
- [ ] 你不确定逻辑到底应该放在哪一层

→ 先读 [跨层思考指南](./cross-layer-thinking-guide.md)

### 什么时候该考虑代码复用

- [ ] 你正在写一段和现有实现很像的代码
- [ ] 你看到同一个模式重复出现 3 次以上
- [ ] 你要在多个地方同步加字段
- [ ] **你正在修改某个常量或配置**
- [ ] **你准备新建一个工具函数 / helper** ← 先搜索

→ 先读 [代码复用思考指南](./code-reuse-thinking-guide.md)

### 什么时候该考虑跨平台问题

- [ ] 会生成或执行脚本
- [ ] 会拼接、存储或比较路径
- [ ] 会依赖 shell 命令
- [ ] 会处理换行、编码或环境变量

→ 先读 [跨平台思考指南](./cross-platform-thinking-guide.md)

## 修改前规则（关键）

> **改任何值之前，都先搜索一遍。**

```bash
# 搜索你即将修改的值
grep -r "value_to_change" .
```

这个习惯可以拦下大多数“漏改了另一个地方”的 bug。

---

## 如何使用这个目录

1. **编码前**：快速浏览相关思考指南
2. **编码中**：如果感觉实现开始重复、复杂或跨边界，就回来看一眼
3. **踩坑后**：把新经验补进相应指南，避免下次再犯

如果你又遇到一个“当时没想到”的坑，把它补充到对应指南里。
