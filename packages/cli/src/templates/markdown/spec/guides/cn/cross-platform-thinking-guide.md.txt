# 跨平台思考指南

> **目标**：在平台相关假设变成 bug 之前先识别出来。

---

## 为什么重要

**大多数跨平台 bug 都来自隐含假设**：

- 以为 shebang 一定可用 → Windows 上失效
- 以为路径分隔符永远是 `/` → Windows 上出问题
- 以为换行永远是 `\n` → 行为不一致
- 以为 shell 语法 everywhere 一样 → 实际并不是

---

## 平台差异检查清单

### 1. 脚本执行

| 假设 | macOS/Linux | Windows |
|------|-------------|---------|
| Shebang (`#!/usr/bin/env node`) | ✅ 可用 | ❌ 会被忽略 |
| 直接执行 (`./script.js`) | ⚠️ 需要可执行权限 | ❌ 会失败 |
| `node` 命令 | ✅ 支持环境中可用 | ✅ 支持环境中可用 |
| Shell alias / wrapper script | ⚠️ 依赖宿主环境 | ⚠️ 依赖宿主环境 |

**规则 1**：面向用户的文档、帮助信息和报错文案里，优先展示显式的 Node 入口，不要假设可以直接执行脚本。

**规则 2**：init 生成配置文件时，文档和运行时都应该使用同一套 Node 命令。

**规则 3**：JavaScript 调用运行时 helper 时，直接调用 Node，而不是依赖 shell wrapper。

**规则 4**：如果要确认 Node 是否已安装，检测的也必须是后续真正会执行的那个 `node`。

### 2. 路径处理

| 假设 | macOS/Linux | Windows |
|------|-------------|---------|
| `/` 分隔符 | ✅ 可用 | ⚠️ 有时可用 |
| `\` 分隔符 | ❌ 会被当作转义 | ✅ 原生分隔符 |
| `path.join` / `path.resolve` | ✅ 可用 | ✅ 可用 |

**规则**：所有路径运算都使用 `node:path`。

### 3. 换行符

| 格式 | macOS/Linux | Windows | Git |
|------|-------------|---------|-----|
| `\n` (LF) | ✅ 原生 | ⚠️ 某些工具有差异 | ✅ 可归一化 |
| `\r\n` (CRLF) | ⚠️ 会出现额外字符 | ✅ 原生 | 会被转换 |

**规则**：跨平台比较或计算 hash 时，先把换行归一化。

### 4. 环境变量

| 变量 | macOS/Linux | Windows |
|------|-------------|---------|
| `HOME` | ✅ 有 | ❌ 应使用 `USERPROFILE` |
| `PATH` 分隔符 | `:` | `;` |
| 大小写敏感性 | ✅ 敏感 | ❌ 通常不敏感 |

**规则**：优先使用 Node 标准库，而不是手工依赖环境变量格式。

### 5. 命令可用性

| 命令 | macOS/Linux | Windows |
|------|-------------|---------|
| `grep` | ✅ 内置 | ❌ 默认不可用 |
| `find` | ✅ 内置 | ⚠️ 语法不同 |
| `cat` | ✅ 内置 | ❌ 通常要用 `type` |
| `tail -f` | ✅ 内置 | ❌ 默认不可用 |

**规则**：只要能用 Node 标准库完成，就不要依赖 shell 命令。
