# Cross-Platform Thinking Guide

> **Purpose**: Catch platform-specific assumptions before they become bugs.

---

## Why This Matters

**Most cross-platform bugs come from implicit assumptions**:

- Assumed shebang works → breaks on Windows
- Assumed `/` path separator → breaks on Windows
- Assumed `\n` line endings → inconsistent behavior
- Assumed shell syntax is the same everywhere

---

## Platform Differences Checklist

### 1. Script Execution

| Assumption | macOS/Linux | Windows |
|------------|-------------|---------|
| Shebang (`#!/usr/bin/env node`) | ✅ Works | ❌ Ignored |
| Direct execution (`./script.js`) | ⚠️ Needs executable bit | ❌ Fails |
| `node` command | ✅ Available in supported setups | ✅ Available in supported setups |
| Shell aliases / wrapper scripts | ⚠️ Host-specific | ⚠️ Host-specific |

**Rule 1**: For user-facing docs, help text, and error messages, show the explicit Node entrypoint instead of assuming direct execution.

```javascript
// BAD - Assumes shebang/direct execution works everywhere
console.log("Usage: ./script.js <args>");
console.log("Run: script.js <args>");

// GOOD - Platform-stable wording
console.log("Usage: node ./.${your-name}/scripts/task.js <args>");
console.log("Run: node ./.${your-name}/scripts/task.js <args>");
```

**Rule 2**: When generating config files at init time, emit the same Node-based command that docs and runtime use:

```typescript
// In template file (settings.json):
{ "command": "node .claude/hooks/script.js" }

// In configurator:
function replacePlaceholders(content: string): string {
  return content.replace(/\{\{HOOK_EXT\}\}/g, "js");
}
```

**Rule 3**: When calling runtime helpers from JavaScript, execute Node directly instead of shell-dependent wrappers:

```javascript
import { execFileSync } from "node:child_process";

execFileSync("node", [scriptPath, "--mode", "phase"], { stdio: "pipe" });
```

**Rule 4**: If you need to verify Node is actually installed, probe the same executable you will later render or execute:

```typescript
function warnIfNodeMissing(): void {
  try {
    execSync("node --version", { stdio: "pipe" });
  } catch {
    // Missing Node is a separate error path; surface it explicitly.
  }
}
```

### 2. Path Handling

| Assumption | macOS/Linux | Windows |
|------------|-------------|---------|
| `/` separator | ✅ Works | ⚠️ Sometimes works |
| `\` separator | ❌ Escape char | ✅ Native |
| `path.join` / `path.resolve` | ✅ Works | ✅ Works |

**Rule**: Use `node:path` helpers for all path operations.

```javascript
// BAD - String concatenation
const filePath = base + "/" + filename;

// GOOD - node:path
import path from "node:path";
const filePath = path.join(base, filename);
```

#### Logical key vs filesystem path (TypeScript)

A path string has two distinct roles. **Treat them differently.**

| Role | OS-native (`\` on Windows) | Always POSIX (`/`) |
|------|---------------------------|--------------------|
| `fs.readFileSync(p)` / `path.join(cwd, x)` for fs call | ✅ Required | ❌ May fail on Windows |
| `Map<relPath, content>` key, JSON field, hash dictionary key, anything persisted across OS | ❌ Cross-OS mismatch | ✅ Required |

**Rule**: Anywhere a path string crosses OS or persists (Map keys consumed by another OS, JSON fields, hash dictionary keys), normalize to POSIX. Anywhere it goes straight to `fs.*`, leave OS-native.

**Single source of truth**: `packages/cli/src/utils/posix.ts` exports `toPosix(p)`. Don't sprinkle `replaceAll('\\', '/')` at every `path.join` site — apply `toPosix` **once at the boundary**: collector exit (Map key entering hash dictionary) or write-time (`saveHashes` before `JSON.stringify`).

```typescript
// BAD - logical key carries OS-native separator
function collectTemplates(): Map<string, string> {
  const files = new Map<string, string>();
  for (const entry of walk(dir)) {
    files.set(path.join(".${your-name}", entry), readFile(entry));
  }
  return files;
}

// GOOD - normalize at the boundary
import { toPosix } from "../utils/posix.js";

function collectTemplates(): Map<string, string> {
  const files = new Map<string, string>();
  for (const entry of walk(dir)) {
    files.set(toPosix(path.join(".${your-name}", entry)), readFile(entry));
  }
  return files;
}
```

**Common offender**: `path.relative(cwd, fullPath)` produces `\` on Windows. If you then use that string as a hash dictionary lookup key (`hashes[relPath]`), `toPosix` it first, or the lookup misses on Windows.

### 3. Line Endings

| Format | macOS/Linux | Windows | Git |
|--------|-------------|---------|-----|
| `\n` (LF) | ✅ Native | ⚠️ Some tools | ✅ Normalized |
| `\r\n` (CRLF) | ⚠️ Extra char | ✅ Native | Converted |

**Rule 1**: Use `.gitattributes` to enforce consistent line endings.

```gitattributes
* text=auto eol=lf
*.sh text eol=lf
*.js text eol=lf
```

**Rule 2**: When hashing or comparing **content** across platforms, normalize line endings before computing the hash.

```typescript
export function computeHash(content: string): string {
  const normalized = content.replace(/\r\n/g, "\n");
  return createHash("sha256").update(normalized, "utf-8").digest("hex");
}
```

### 4. Environment Variables

| Variable | macOS/Linux | Windows |
|----------|-------------|---------|
| `HOME` | ✅ Set | ❌ Use `USERPROFILE` |
| `PATH` separator | `:` | `;` |
| Case sensitivity | ✅ Case-sensitive | ❌ Case-insensitive |

**Rule 1**: Use `os.homedir()` instead of environment variables.

```javascript
import os from "node:os";

const home = os.homedir();
```

**Rule 2**: When injecting environment variables into shell commands, generate the prefix for the actual shell that will parse the command. Do not choose syntax from OS alone.

```javascript
const prefix = process.platform === "win32" && !isWindowsPosixShell(process.env)
  ? `$env:HARNESS_SPEC_CONTEXT_ID = ${powershellQuote(contextKey)}; `
  : `export HARNESS_SPEC_CONTEXT_ID=${shellQuote(contextKey)}; `;
command = `${prefix}${command}`;
```

### 5. Command Availability

| Command | macOS/Linux | Windows |
|---------|-------------|---------|
| `grep` | ✅ Built-in | ❌ Not available |
| `find` | ✅ Built-in | ⚠️ Different syntax |
| `cat` | ✅ Built-in | ❌ Use `type` |
| `tail -f` | ✅ Built-in | ❌ Not available |

**Rule**: Use the Node standard library instead of shell commands when possible.

```javascript
async function tailFollow(filePath) {
  const fs = await import("node:fs/promises");
  let position = (await fs.stat(filePath)).size;
  for (;;) {
    const handle = await fs.open(filePath, "r");
    const buffer = Buffer.alloc(4096);
    const { bytesRead } = await handle.read(buffer, 0, buffer.length, position);
    await handle.close();
    if (bytesRead > 0) {
      process.stdout.write(buffer.subarray(0, bytesRead).toString("utf8"));
      position += bytesRead;
    } else {
      await new Promise((resolve) => setTimeout(resolve, 100));
    }
  }
}
```

### Optional Advisory Checks in Agent Sandboxes

AI CLI subprocesses may run with outbound network disabled even when the user's normal terminal has network access. Prefer local CLI probes over optional network probes when the local CLI already exposes the needed information.

**Rule 1**: Do not let a failed optional advisory check consume a once-per-session marker.

**Rule 2**: If a local command can provide the needed value, try it with a short timeout and captured output. For example, `harness-spec --version` already runs the CLI's version comparison logic and can support an actionable update prompt without duplicating registry parsing.

**Rule 3**: Keep advisory checks silent on failure.

### 6. File Encoding

| Default Encoding | macOS/Linux | Windows |
|------------------|-------------|---------|
| Terminal | UTF-8 | Often CP1252 or GBK |
| File I/O | UTF-8 | System locale |
| Git output | UTF-8 | May vary |

**Rule**: Always explicitly specify UTF-8 when you expect text.

```javascript
const content = fs.readFileSync(file, { encoding: "utf8" });
const result = execFileSync(cmd, args, { encoding: "utf8", stdio: "pipe" });
```

**Git commands**: Force UTF-8 output encoding:

```javascript
const result = execFileSync(
  "git",
  ["-c", "i18n.logOutputEncoding=UTF-8", ...args],
  { encoding: "utf8", stdio: "pipe" }
);
```

## Change Propagation Checklist

When making platform-related changes, check **all these locations**:

### Commands / Skills Sync
- [ ] New command/skill added to all supported platforms (claude, codex, gemini)
- [ ] Each platform's test file updated with new entry in `EXPECTED_COMMAND_NAMES` / `EXPECTED_SKILL_NAMES`
- [ ] Platform-integration spec's required command table updated if adding a new required command
- [ ] Command format matches platform convention

### Documentation & Help Text
- [ ] Docstrings/comments at top of Node runtime files when needed
- [ ] `--help` output / CLI descriptions
- [ ] Usage examples in README
- [ ] Error messages that suggest commands
- [ ] Markdown documentation (`.md` files)

### Code Locations
- [ ] `src/templates/` - Template files for new projects
- [ ] `.${your-name}/scripts/` - Project's own scripts (if self-hosting)
- [ ] `dist/` - Built output (rebuild after changes)

### Search Pattern
```bash
rg -n "node .*\\.js|\\.${your-name}/scripts/" --glob "*.md" --glob "*.txt"
rg -n "HARNESS_SPEC_CONTEXT_ID|hookSpecificOutput" --glob "*.ts" --glob "*.js"
```

## Pre-Commit Checklist

Before committing cross-platform code:

- [ ] User-facing runtime script invocations use `node ./.${your-name}/scripts/*.js`
- [ ] Node subprocesses use argument arrays instead of shell-joined strings when possible
- [ ] All paths use `node:path`
- [ ] No hardcoded path separators (`/` or `\`)
- [ ] Path strings used as logical/persisted keys are normalized via `toPosix()`
- [ ] Content hashes computed across OSes normalize line endings (`\r\n` → `\n`) before hashing
- [ ] Cross-OS JSON with potential legacy pollution carries a `__version` sentinel when safe
- [ ] No platform-specific commands without fallbacks (e.g., `tail -f`)
- [ ] Optional advisory checks do not burn once-per-session markers on failure
- [ ] All file I/O specifies UTF-8 when reading text
- [ ] All subprocess calls that expect text request UTF-8 output
- [ ] Git commands use `-c i18n.logOutputEncoding=UTF-8`
- [ ] External tool API formats verified from documentation
- [ ] Documentation matches code behavior
- [ ] Ran search to find all affected locations

### 7. External Tool API Contracts

When integrating with external tools (Claude, Codex, Gemini, etc.), their API contracts are **implicit assumptions**.

**Rule**: Verify API formats from official documentation, don't guess.

```javascript
const output = {
  hookSpecificOutput: {
    hookEventName: "SessionStart",
    additionalContext: "..."
  }
};
```

> **Warning**: Different hook types may have different output formats.
> Always check the specific documentation for each hook event.

## Cross-Platform Persisted JSON: Schema Migration Sentinel

When a JSON file may be read/written across OSes and an older format may already exist on user disks with cross-platform pollution (Windows-style keys, CRLF-derived hashes, locale-encoded strings), add a `__version` sentinel and let the loader discard old formats so the writer regenerates clean data.

```typescript
const SCHEMA_VERSION = 2;
type StoredV2 = { __version: number; hashes: Record<string, string> };
```

Use this only when the data is recomputable.

---

## JSON/External Data Defensive Checks

When parsing JSON or external data, TypeScript types are **compile-time only**. Runtime data may not match.

```typescript
if (!item.from) return;
```

Check existence first, then use the field.

## Common Mistakes

### 1. "It works on my Mac"

```javascript
execFileSync("./script.js");  // Works locally
execFileSync("node", ["./script.js"]);  // Works portably
```

### 2. "The shebang should handle it"

```javascript
#!/usr/bin/env node
// This line is ignored on Windows
```

### 3. "I updated the template"

```text
src/templates/script.js         <- Updated
.${your-name}/scripts/script.js <- Forgot to sync
```

### 4. "Direct execution works everywhere"

```bash
node script.js
```

Prefer showing the real entrypoint everywhere in docs and config.

### 5. "UTF-8 is the default everywhere"

```javascript
execFileSync(cmd, args); // Implicit Buffer/string handling becomes inconsistent
```

---

## Recovery: When You Find a Platform Bug

1. **Fix the immediate issue**
2. **Search for similar patterns**
3. **Update this guide** with the new pattern
4. **Add to pre-commit checklist** if recurring

---

**Core Principle**: If it's not explicit, it's an assumption. And assumptions break.
